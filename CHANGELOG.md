# Changelog — История изменений

## [3.9.44] - 2026-06-01

### Добавлено
- **Расширенный редактор (CodeMirror 6) в редакторе задач** (`TaskEditModal`) —
  тумблер «Расширенный редактор» вверху модалки переключает поля «Текст задания»
  и «Решение» с обычной `Input.TextArea` на CodeMirror 6: подсветка markdown,
  перенос длинных строк, авторазмер и встроенный поиск/замена (Ctrl+F / Ctrl+H).
  Поле «Ответ» (однострочное) намеренно не затронуто. Выбор режима запоминается
  в `localStorage` (`taskEditor.codeMode`).
  - Новый общий компонент `components/shared/LatexField.jsx` (проп `mode='plain'|'code'`,
    наружу — обычное поле формы `value`/`onChange` + `onTextChange` для предпросмотра).
    CodeMirror вынесен в `components/shared/LatexCodeMirror.jsx` и грузится **лениво**
    отдельным чанком (~212 KB gzip) — в основной бандл не попадает.
- **Подсветка «сломанного» LaTeX в расширенном редакторе** — линтер на базе KaTeX:
  каждая формула `$…$` / `$$…$$` прогоняется через `katex.renderToString`; не
  парсится → красное подчёркивание с текстом ошибки KaTeX, непарный `$` → жёлтое
  предупреждение «формула не закрыта». Маркер ошибки в gutter слева.
  Новая утилита `utils/katexLint.js` (`katexDiagnostics`), 8 юнит-тестов.

## [3.9.43] - 2026-06-01

### Добавлено
- **Кнопки «🧹 Корни» в редакторе задач** (`TaskEditModal`) — детерминированная
  починка битых корней/иррациональных выражений из плохого парсинга sdamgia,
  мгновенно и без сети. Покрывает три формата маркеров аргумента (обычные пробелы,
  мягкие переносы, слипшийся текст) и Unicode `√/∛/∜`.
  Пример: `\log_{\sqrt: начало аргумента: 3 конец аргумента}` → `\log_{\sqrt{3}}`.
  - Своя кнопка у каждого поля: «Текст задания», «Ответ», «Решение» — чинит только
    своё поле. В шапке текста задания дополнительно «🧹 Ответ+решение» — чинит оба
    нижних поля разом.
  - Новая утилита `utils/fixLatexRoots.js` (`fixLatexRoots`, `hasBrokenRoots`),
    13 юнит-тестов. Клиентский аналог части серверной `cleanLatexFormula`, но
    толерантный к пробельному варианту маркера без мягких переносов (его серверные
    regex'ы пропускали).

### Исправлено
- **КИМ-печать показывала устаревший текст задачи после правки через редактор**
  (`EgeVariantGenerator` база + `EgeProfileVariantGenerator` профиль). Ключ measure-
  фазы пагинации (`taskKey`) строился только по `id` задач, а `id` при редактировании
  не меняется → перерасчёт не запускался и печатались закэшированные старые страницы.
  Теперь ключ включает содержимое (`statement_md`, картинку, для профиля `solution_md`)
  — любая правка триггерит пересчёт со свежими задачами. (Обычные «листы работ» в
  Генераторе обновлялись корректно и раньше — там рендер читает варианты живьём.)

## [3.9.38] - 2026-05-29

### Дедуп-вкладка: удалённые задачи скрываются сразу

`/duplicates` теперь фильтрует из кластеров задачи, которых уже нет в базе
(удалённые): пустые строки «—» не показываются, размер кластера («N задач»)
считается по живым, кластеры с <2 оставшимися пропадают. Происходит на
каждом запросе (живой JOIN), поэтому удалённые задачи исчезают из вкладки
**при перезагрузке** — без ожидания и без пересчёта дублей. (Вектор в vec.db
убирается отдельно прунингом на агенте ≤30 мин — это про место, не про вкладку.)

### Пересчёт дублей — ручной (по запросу учителя)

Дедуп-кластеры обновляются **только вручную**, когда учитель сам решит
(тяжёлая O(n²) кластеризация ~5-6 мин — не место для авто на каждом импорте):
- команда: **`cd vector-benchmark && npm run dedup`** (= `index.mjs --push --dedup`);
- считается **на Mac** (локальная vec.db) → заливается на VPS ручкой
  `POST /upload-clusters` (токен, ретрай ×3). VPS не грузится — только пишет
  файл (серверный пересчёт вешал event loop pdf-service, отказались);
- launchd-агент (индекс векторов, ≤30 мин) дубли **НЕ** трогает;
- токен для ручного запуска берётся из `vector-benchmark/.index-token`
  (gitignored), вводить не нужно.
Индекс векторов (A1/A2/A4/C4) при этом по-прежнему обновляется авто-агентом.

### Дедуп-вкладка: массовое удаление + без рефреша

- У каждой задачи в кластере — **чекбокс**; выбрал несколько → панель
  «Удалить выбранные (N)» одной кнопкой. Кнопка «Выбрать всех сирот»
  (ref_count=0, безопасно удаляемые).
- **Удаление больше не рефрешит страницу** — задачи убираются из локального
  состояния (кластеры с <2 задач уходят сами). И одиночная 🗑, и массовое.
- Используемые в работах задачи в массовом режиме пропускаются (БД не даёт),
  в итоге показывается «удалено N, не удалось M».

## [3.9.35] - 2026-05-29

### A4: создание параллельных вариантов как работ в «Мои работы»

Модал «Параллельные варианты» теперь доводит дело до результата:
- кнопка **«Создать работы в Мои работы»** создаёт работы из образца и
  параллелей: «<название> — оригинал», «— дубль 1», «— дубль 2» …
- если запущено из сохранённой работы («Мои работы» → 🧬) — исходная
  помечается оригиналом и не дублируется; из генераторов — оригинал
  создаётся из образца;
- после создания — список работ с ролями и кнопками «Открыть»;
- связь сохраняется и на уровне задач (`variant_family`, роли base/parallel_N).
Поле «Название» редактируется. Закрыта дыра «куда делось семейство» —
результат теперь в «Мои работы».

### A4: ручной подбор задач в параллельных вариантах

В модале «Параллельные варианты» теперь нет «дырок»:
- пустой слот (нет похожей задачи) → кнопка **«Выбрать»** → каталог задач
  (`TaskSelectModal`) → подставляется в ячейку (бейдж «вручную»);
- у любой подобранной задачи — кнопка **«заменить»** (↻) → тот же каталог;
- уже занятые в семействе задачи исключаются из выбора (без повторов).
Заполненные вручную задачи попадают в «Сохранить как семейство».

### Дедуп-вкладка: ссылки на работы + «Не дубли» сохраняется

- У каждой задачи в кластере — **кликабельные чипы работ**, где она
  используется (`works` в `/duplicates`): клик открывает редактор работы
  (там можно заменить/убрать задачу через `TaskReplaceModal`). Зелёный
  «не используется» = можно удалять.
- **«Не дубли» теперь персистится** (новый тип `reviewed_not_dup` в
  `task_families`, миграция 1779000005): помеченный кластер больше не
  возвращается в очередь ревью (раньше скрывался только в текущей сессии).
  `/duplicates` фильтрует кластеры, чьи члены уже в `dedup_cluster` ИЛИ
  `reviewed_not_dup`. `api.markNotDuplicate`.

### Редактор задач и чистка дублей в дедуп-вкладке

В вкладке «🔎 Похожие (вектор)» (каталог) теперь можно править/удалять задачи
прямо из кластера:
- у каждой задачи бейдж **«в N работах»** (`ref_count` в `/duplicates` —
  считает ссылки в `variants.tasks`): красный «в N раб.» = удаление урежет
  работы (безопаснее «Пометить дублями»), зелёный «не исп.» = можно удалять.
- кнопка ✏️ открывает существующий `TaskEditModal` (правка / удаление /
  починка LaTeX, с audit-логом). После удаления очередь обновляется.

**Прунинг осиротевших векторов:** удалённые задачи больше не оставляют
«мусорные» векторы. `index.mjs --push` собирает актуальные id и зовёт
`POST /prune-vectors` (токен) — на каждом launchd-прогоне (30 мин) vec.db
самоочищается. (Поиск и так игнорировал осиротевшие через JOIN — это гигиена.)

### Работа над ошибками с похожими задачами (C4, фаза 1)

В модал «Работа над ошибками» (страница ученика) добавлен подбор **похожих
задач для свежей отработки**: кнопка «Подобрать» по выбранным проваленным
задачам → для каждой подбираются 2 похожие (тот же навык, другие числа —
cos 0.70–0.97), с чекбоксами. Итоговая работа = проваленные + выбранные
похожие; выдача ученику (сессия + ссылка) как раньше.
- pdf-service: `POST /remediation { failed_task_ids, per_task, exclude_ids? }`
  — KNN внутри темы в полосе «тот же навык, не клон», сгруппировано по
  исходной задаче, дедуп, без оригиналов.
- `StudentDetailPage`: секция «🩹 Похожие для отработки» в существующем
  модале (реюз `createWork`/`createVariant`/`createSession`).

**Класс-режим (фаза 3):** в результатах сессии (`TeacherResultsDashboard`) —
кнопка «🩹 Работа над ошибками класса»: агрегирует провалы по всем попыткам,
показывает частые ошибки (≥ порога, по умолчанию 40%), подбирает похожие и
создаёт одну работу + сессию на весь класс. `ClassRemediationModal` (новый).

## [3.9.34] - 2026-05-29

### Семейство параллельных вариантов «по образцу» (A4)

Кнопка **«🧬 Параллельные варианты (по образцу)»**: для каждой задачи образца
подбирается похожая (та же тема и тип, другие числа — cos 0.85–0.995),
собираются N параллельных вариантов. Сценарий: подготовка → контрольная →
пересдача.
- pdf-service: `POST /parallel-variants { task_ids, count, min_cos?, max_cos? }`

## [3.9.33] - 2026-05-28

### Фикс дубликата картинок в импортированных sdamgia-задачах

Symptom: после импорта задачи карточка показывала одну и ту же картинку
дважды — один раз inline через markdown, второй раз отдельным `<Image>` под
условием. Заметно на ЕГЭ-База и ЕГЭ-Профиль (часть 1) — везде где `processCondition`
извлекает картинку.

**Причина:** в v3.9.31 серверный `processCondition` оставлял `![image](url)`
прямо в тексте `condition` markdown «для backward-compat». Но 34 места рендера
условия (TaskCard, EgeVariantGenerator, PrintableWorksheet, MarathonGenerator
и др.) исторически ожидают **чистый текст + отдельный `<Image>`** из file-поля
`tasks.image` — этот контракт держится с самого первого markdown-парсера, где
картинка всегда **вырезалась** из statement_md и сохранялась отдельно.

**Фикс** (`pocketbase/pdf-service.js`):
- В `processCondition` маркер `___IMAGE_N___` теперь заменяется на пустую
  строку, а не на `\n![image](${fullUrl})\n`. Картинки остаются доступны через
  `condition_images` массив (для `TaskEditModal` и `RefreshFromSdamgiaModal`,
  которые используют `TaskStatementRenderer` с подменой URL).

**Миграция уже импортированных задач** (`migrations_scripts/strip_inline_image.py`):
- Безопасный скрипт с dry-run / `--apply` режимами. Перед удалением проверяет
  что у задачи есть либо `image` file, либо запись в `task_images` с
  role='condition' — иначе пропускает (защита от потери картинки).
- На VPS: 3369 sdamgia-задач, 286 с inline ![image], **у всех 286 локальная
  копия есть** (0 опасных случаев). Все 286 обновлены за один прогон.
- Бэкап БД: `pre_image_dedup_20260528_231544.db` (27 МБ).

### Геометрия — SVG-конвертер GeoGebra

Новый модуль `utils/ggbToSvg.js` — конвертация GeoGebra XML в векторный SVG через JSXGraph без открытия браузерного апплета. Результат хранится в поле `drawing_svg` (до 200 KB) и рендерится в рабочем листе и просмотре без зависимости от GeoGebra API.

**Поддерживаемые объекты:** точки, отрезки, лучи, прямые, полигоны, углы (прямые — квадратик, обычные — дуга).

**Нюансы конвертации:**
- Раздельные масштабы X/Y (`scale` / `yscale` из `<coordSystem>`) — корректно обрабатываются
- Текстовые подписи: GeoGebra 6 хранит содержимое в `<expression exp="...">`, GeoGebra 5 — в `<textExpression val="...">` (поддержаны оба формата); `{,}` → `,`
- Засечки равенства на отрезках (`<decoration type="1|2|3"/>`) — 1/2/3 черточки перпендикулярно середине, инжектируются как SVG `<line>`
- Позиции вершинных меток берутся напрямую из `labelOffset` GeoGebra (без эвристических переопределений)
- Направление дуги угла: `<angleStyle val="0">` = CCW (обычный), `val="1">` = CW — при CW меняются местами `ptFrom`/`ptTo` в JSXGraph
- Подписи вершин: `font-size=15`, `font-weight=bold` — крупнее и жирнее свободных текстов

**Интеграция:**
- `GeometryTaskEditor` — кнопка «Конвертировать в SVG» запускает `ggbXmlToSvg(xml)`, SVG-превью показывается под апплетом; кнопка «Сохранить SVG» сохраняет в БД и переключает `drawing_view='svg'`
- `TabDrawing` — новый режим «SVG (векторный)» в переключателе `drawing_view`; доступен только после конвертации
- `GeometryWorksheetPrint` — SVG-чертёж рендерится через `dangerouslySetInnerHTML` (масштабируется так же, как PNG)
