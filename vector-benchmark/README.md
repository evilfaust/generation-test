# Векторный поиск Lemma — индексатор

Этот скрипт обновляет «умный» поиск задач: «Похожие задачи», «Параллельные
варианты», предупреждение о повторах, дедуп-вкладка. Считает эмбеддинги задач
(модель `bge-m3`, 1024 чисел на задачу) **на этом Mac** через Ollama, хранит их
в локальной `data/vec.db` и отправляет на VPS, где работает сайт.

> ⚠️ **Запускается только вручную.** Раньше был автозапуск каждые 30 минут
> (launchd-агент `com.lemma.vecindex`) — его убрали. Теперь индексацию
> запускаешь ты сам, когда добавил/изменил задачи.

---

## TL;DR — что запускать

Открой Терминал и выполни:

```bash
cd ~/Documents/APP/generation-test/vector-benchmark
npm run index
```

Это и есть обычный режим: посчитать только новые/изменённые задачи и отправить
их на VPS. Занимает от нескольких секунд (если нового нет) до пары минут.

Когда закончит — увидишь `✅ Готово`. Всё, поиск на сайте обновлён.

---

## Что происходит при запуске (по шагам)

Скрипт всё подписывает, так что в Терминале видно, на каком он этапе:

```
🔍 Проверяю окружение      — доступны ли Ollama, PocketBase, есть ли токен
[1/4] Загружаю задачи       — тянет список задач из базы Lemma
[2/4] Сравниваю             — определяет, что новое/изменилось
[3/4] Считаю эмбеддинги     — прогон через Ollama (с прогрессом и ETA)
[4/4] Отправляю на VPS      — заливает новые вектора, чистит удалённые
✅ Готово                   — итог: сколько посчитано/отправлено
```

Если что-то не так (Ollama не запущена, нет интернета, нет токена) — скрипт
честно скажет, что именно, и не будет молча висеть.

## Все режимы запуска

| Команда | Что делает | Когда нужно |
|---|---|---|
| `npm run index` | Инкремент + отправка на VPS | **Обычно. После добавления задач.** |
| `node index.mjs` | Инкремент локально, **без** отправки | Проверить, ничего не меняя на сайте |
| `node index.mjs --full --push` | Пересчитать **все** задачи заново + отправка | Сменили модель / база рассинхронилась |
| `npm run dedup` | Всё выше + пересчёт кластеров дублей | Перед работой с вкладкой «Похожие (вектор)» |
| `node index.mjs --help` | Показать справку | — |

> `npm run dedup` тяжёлый (перебор всех пар, ~5-6 минут) — запускай только когда
> реально нужно обновить дедуп-вкладку, не на каждый импорт.

## Что будет, если я отредактирую задачу

Коротко: **`npm run index` подхватит изменения сам.** Он сравнивает не «новая/старая»,
а **хеш текста** каждой задачи (тема + условие) с тем, что был при прошлой
индексации:

- текст изменился → хеш не совпал → задача пересчитывается и заливается на VPS;
- текст не менялся → пропускается.

Так что отредактированное условие, исправленный кривой LaTeX от парсера, смена
темы — всё это переиндексируется при следующем прогоне. «Неправильный» вектор
живёт ровно до следующего `npm run index`.

Что попадает в вектор (и в хеш) — **тема + условие** (`statement_md`). Поэтому:

| Что поменял | Пересчитается? |
|---|---|
| Условие задачи | ✅ да |
| Тему задачи | ✅ да |
| Исправил LaTeX в условии | ✅ да |
| Только ответ | ❌ нет (вектор от ответа не зависит) |
| Теги / сложность / источник | ❌ нет (на смысл условия не влияют) |

Удалённые задачи тоже обрабатываются — в конце прогона их вектора убираются
и локально, и на VPS (прунинг).

> ⚠️ Важно: «память» о хешах хранится в локальной `data/vec.db` на этом Mac.
> Поэтому запускай индексатор всегда с одной машины. Если очень много правил
> или кажется, что что-то рассинхронилось — `node index.mjs --full --push`
> пересчитает всё с нуля (дорого по времени, но это «кнопка истины»).

## Что нужно, чтобы это работало

- **Node.js 18+** (`node -v`).
- **Ollama с моделью `bge-m3`.** Проверить: `ollama list`. Если модели нет:
  `ollama pull bge-m3`. Ollama должна быть запущена (приложение или `ollama serve`).
- **Интернет** (база и VPS — на сервере `task-ege.oipav.ru`).
- **Файл `.index-token`** рядом с этим README — секретный токен для отправки на
  VPS (совпадает с `INDEX_TOKEN` на сервере). Уже есть; в git не попадает.

---

## Если что-то пошло не так

- **`❌ Ollama недоступна`** — запусти приложение Ollama (или `ollama serve`),
  проверь `ollama list` (нужна `bge-m3`).
- **`❌ PocketBase недоступен`** — нет интернета/VPN, или сервер лежит.
- **`❌ Нет токена для отправки на VPS`** — пропал файл `.index-token`. Токен
  лежит на VPS в systemd-override pdf-service; восстанови файл из него.
- **Посчиталось, но сайт не видит** — скорее всего запускал без `--push`
  (тогда меняется только локальная база). Запусти `npm run index`.

## Подсказка: алиас для быстрого запуска

Чтобы не печатать длинный путь, можно добавить в `~/.zshrc`:

```bash
alias vecindex='cd ~/Documents/APP/generation-test/vector-benchmark && npm run index'
```

Потом перезапустить Терминал — и индексировать командой `vecindex`.

## Переменные окружения (по умолчанию менять не нужно)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PB_URL` | PocketBase | `https://task-ege.oipav.ru` |
| `OLLAMA_URL` | Ollama | `http://localhost:11434` |
| `EMBED_MODEL` | модель эмбеддингов | `bge-m3` |
| `PDF_URL` | pdf-service на VPS (push) | `https://task-ege.oipav.ru/pdf` |
| `INDEX_TOKEN` | токен (или из `.index-token`) | — |
| `THRESHOLD` | порог косинуса для дублей | `0.82` |
